# 职途 AI 用户指南

本指南同时面向第一次使用的求职者、查看项目的 HR/老师，以及需要演示完整流程的维护者。

## 1. 先理解三个对象

- **简历**：可复用资产，可以为具体机会创建新版本。
- **机会**：一家公司的一份岗位，连接 JD、简历、面试、投递阶段和时间线。
- **Agent**：读取当前上下文、给出下一步建议并创建待确认操作，不会跳过确认直接改数据。

最有效的用法不是先和 Agent 闲聊，而是先建立职业档案、简历和一个真实机会，让建议有事实依据。

## 2. 第一次启动

Windows 用户双击 `start.bat`。启动器检查 Python 3.10+ 和依赖，自动选择安全端口并打开默认浏览器。若未自动打开，查看窗口中显示的本地地址。

首次进入后建议：

1. 选择求职方向。
2. 在总览或 Agent 中补充目标岗位、城市和薪资偏好。
3. 进入“简历实验室”保存一份简历。
4. 进入“投递看板”创建一个真实或脱敏的练习机会，并粘贴 JD。

## 3. 推荐求职流程

### 建立职业档案

职业档案决定系统使用什么岗位语言理解你的经历。信息不完整时，准备度会明确列出阻塞项，而不是仅靠记录数量给高分。

### 保存和分析简历

可以粘贴文本或上传 PDF、Word、TXT。分析重点是结构、岗位证据、量化结果、关键词覆盖和风险，不把分数当作录用概率。

处理个人简历时请注意：文件和解析内容存放在本机；若启用远程模型，相关上下文可能发送给所选模型供应商。

### 创建机会并粘贴 JD

每个岗位建立独立机会。机会工作区的“概览、JD、简历、面试、时间线”页签让关联关系可检查。不要把多个公司的 JD 放在同一机会里，否则匹配和复盘会失真。

### 为机会准备简历版本

先查看 JD 匹配证据，再让 Agent 或简历模块提出修改方向。Agent 创建的是“简历版本提案”，确认前可查看预览；原简历不会被静默覆盖。

### 面试训练

从机会工作区进入面试可以保留岗位关联。会话每次回答后持久化，刷新或服务重启后可以恢复。浏览器不支持语音识别或录音时，使用文字回答或上传音频即可。

回答“不知道”“跳过”或“下一题”时，系统会按跳过流程处理并提供参考方向，不应把空回答包装成优秀表现。

### 更新投递阶段并复盘

统一阶段为：意向、准备中、已投递、简历筛选、笔试、一面、二面、HR 面、Offer、已拒绝、已结束。历史数据中的未知状态显示在“待确认”，由用户决定如何修正。

阶段更新、面试完成和简历版本创建会进入时间线，相关行动项在关联明确时自动完成。

## 4. 如何使用全局 Agent

桌面端从右侧打开，移动端以底部面板显示。顶部上下文标签说明 Agent 当前参考的模块、机会和简历；不需要的标签可以移除。

适合的请求：

- “根据当前机会告诉我最影响投递的三个缺口。”
- “为这个 JD 创建一份简历修改版本。”
- “基于最近面试低分项安排三天训练计划。”
- “把当前机会推进到已投递，并记录明天下午跟进。”
- “生成本周求职复盘，区分事实和建议。”

如果 Agent 显示操作卡片：

1. 检查目标对象、修改内容和风险提示。
2. 只编辑界面允许的安全字段。
3. 选择“确认执行”或“取消”。
4. 执行后点击结果链接检查对应机会或时间线。

刷新后，待确认卡片会从消息元数据和提案存储中恢复。重复点击确认不会重复创建同一结果。

## 5. 本地模式与远程模型

左下角显示当前模式。未配置 Key 时，本地 Agent 可以识别常见求职问法，连续读取看板、职业目标、行动项和训练记录，生成求职诊断、机会盘点、面试准备、简历建议和动作提案；对开放式表达、复杂语义和个性化措辞的处理仍有限。

推荐直接提问：`帮我分析现在的求职情况，下一步做什么`、`看看我的机会和投递进展`、`面试准备得怎么样`、`帮我优化简历`。

配置远程模型后，Agent 可以更灵活地选择工具和组织答案。模型服务故障时系统会返回可诊断状态或降级，不会冒充调用成功。

页面输入的 Key 仅存在当前 Python 进程内存中，退出后失效。环境变量适合固定的本机开发环境。不要把真实 Key 写进源码、截图、Issue 或提交记录。

## 6. 浏览器说明

核心功能支持当前版本的 Microsoft Edge、Google Chrome 和 Mozilla Firefox。建议使用桌面浏览器完成简历上传和长文本编辑。

- Edge/Chrome 通常可使用 Web Speech 语音识别，但仍取决于系统和浏览器服务。
- Firefox 通常没有同等语音识别能力，界面会隐藏不可用按钮并保留文字输入。
- 录音格式由能力检测选择；若浏览器录音不可用，可以上传音频。
- 移动视口下 Agent 为底部面板，关闭后焦点会回到原操作位置。

## 7. 文件转换

PDF/Word 转换受原文件结构、字体和操作系统影响。Windows 安装 Microsoft Word 时，Word 转 PDF 可优先使用 Office 提升保真度；未安装时使用项目内置转换能力。导出前仍应人工检查分页、字体和表格。

## 8. 隐私与备份

主要本地数据：

- `jobhunter.db`：业务数据、Agent 会话、记忆和回执。
- `uploads/`：上传的简历和音频。
- `exports/`：导出的文档。
- `output/runtime/`：启动和服务日志。

迁移旧数据库前系统会在适用场景生成版本备份。手工备份时应先正常关闭服务，再复制数据库和需要保留的上传文件。公开分享项目时，只分享 Git 跟踪文件，不要打包上述本地数据。

## 9. 常见问题

**Agent 只给本地模板回答**

检查左下角模式和“模型配置”。无 Key、本机断网、供应商失败或模型 ID 不可用时会保持或退回本地模式。

**待确认操作无法加载**

先重试。只有明确的 404/403 会清理无效上下文；网络或服务错误会保留工作区和 URL。仍失败时查看 `output/runtime/server-error.log`。

**启动端口被占用**

启动器不会结束其他程序，会选择后续可用端口。也可运行 `.\start.bat -Port 5050`。

**语音按钮不可用**

这是能力降级，不影响文字回答和音频上传。确认浏览器已允许麦克风，并优先尝试最新版 Edge 或 Chrome。

**能否部署给多人使用**

当前不能。系统没有登录和多租户认证，默认固定本地用户。多人或公网部署前必须增加认证、授权、HTTPS、密钥存储和数据隔离。

## 10. HR / 老师建议体验路线

1. 在展示页查看真实桌面与移动截图。
2. 打开总览，观察准备度证据和阻塞项。
3. 进入一个机会工作区，查看 JD、关联简历、面试和时间线。
4. 打开全局 Agent，要求它为当前机会提出下一步操作。
5. 检查提案预览，确认后观察业务页面和时间线同步更新。
6. 刷新页面，验证会话、面试和待确认操作仍可恢复。
