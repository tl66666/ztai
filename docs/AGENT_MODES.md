# Agent 双模式说明

职途 AI 将“能可靠完成的本地任务”和“需要开放语言理解的模型能力”分开处理。是否配置 API Key 不影响核心求职流程；它决定的是哪些任务可以获得模型增强。

## 无 API Key：本地可验证执行

没有 Key 时，系统不会伪装成已经调用大模型。Agent 仍可读取本机 SQLite 中的权威业务数据，并通过确定性流程完成：

- 求职准备度诊断、职业目标、行动项、面试训练和投递记录盘点；
- 简历选择、结构与证据诊断、事实保真草稿、JD 要点与岗位匹配；
- 基于已选简历生成定制面试题、读取题库和评估结构化回答；
- 创建需要用户确认的简历版本、行动项或机会操作提案；
- 时间、问候和常见使用引导。

这些任务优先本地执行，即使已经配置模型也一样。这样可以避免不必要的网络等待、减少敏感数据外发，并让结果保持可复现。

## 配置 API Key：模型增强生成

配置 GLM、DeepSeek 或 Kimi/Moonshot 后，Agent 会把需要开放理解和表达的请求交给模型，例如：

- 通读完整简历，围绕目标岗位生成完整改写稿；
- 处理不在本地意图库中的开放问题、复杂职业表达和多轮追问；
- 在允许的结构化工具范围内选择工具并综合工具返回的资料。

模型调用始终受工具 Schema、总时长、重复调用预算和写入确认机制约束。模型不可用、超时或返回不可靠内容时，运行时会保留已取得的结果，并退回本地策略，而不是无限重试。

## 数据与隐私

- 页面输入的 Key 不写入 SQLite、不写入浏览器存储、不提交到 Git。
- 为支持重启后复用，页面配置会保存在 Git 忽略的本机 `output/runtime/ai-config.json`。该文件包含明文 Key，应和数据库、上传文件一样仅由当前电脑用户保管；在“模型配置”中留空保存即可清除。
- 使用环境变量配置时，Key 由启动进程读取。远程模型请求会把完成该请求所需的消息、裁剪后的上下文和工具结果发送到所选供应商。
- Agent 不能直接写业务表；任何创建或更新都必须经过“提议、预览、用户确认、领域服务执行、回执”链路。

## 选择建议

日常整理简历、查看进度、按已有内容出题或推进确定性流程时，不配置 Key 也能稳定使用。需要完整简历深度改写、开放式职业教练或更自然的长文本表达时，再配置可信供应商的 Key。

## 产品入口与分工

系统只有一个“求职 Agent”，不是“AI 教练”和 Agent 两套模型：

- 右侧 **求职 Agent** 工作台负责对话、读取页面上下文、选择工具、生成草稿和提出待确认操作。
- 左侧 **求职指挥台** 是运行看板，集中显示 Agent 已准备的操作、进行中的机会和确认结果；它不重复提供聊天入口。
- **面试训练场**保留教练式反馈，但只围绕具体回答、语音表达和训练复盘，不承担跨模块的 Agent 编排。
