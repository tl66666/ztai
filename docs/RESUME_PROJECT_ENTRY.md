# 简历项目素材：职途 AI Agent 求职工作台

这份文档用于简历、作品集、面试自我介绍和项目展示页。项目标题、技术栈和数字均以当前仓库实现为准，后续版本更新时优先修改这里，再同步简历。

## 项目标题

职途 AI Agent 求职工作台（JobHunter）

## 项目概述

面向真实求职流程设计的本地优先 Web 系统，将职业目标、简历、JD 匹配、模拟面试、投递机会和复盘行动连接成一条可追踪流程。核心 Agent 不是独立聊天窗口，而是嵌入各业务模块的上下文助手：能够读取实时业务数据和分层记忆，调用 21 个求职工具，识别缺失信息并推进下一步；涉及数据写入时先生成提议和预览，经用户确认后由领域服务执行。

## 技术栈

Python / Flask / SQLite / SQLite FTS5 / 原生 JavaScript / HTML5 / CSS3 / Web Speech / MediaRecorder / Playwright / 多模型 API（GLM、DeepSeek、Kimi）/ Windows PowerShell 启动器

## 核心亮点

- 自研 Python Agent Runtime：由 `ContextBuilder`、`MemoryStore`、`Orchestrator` 和 `ToolRegistry` 组成，采用有界工具循环、严格参数 Schema、超时和重复调用预算，支持原生 `tool_calls` 与无 Key 确定性多工具规划。
- 分层持久记忆：区分工作、摘要、语义、情景、任务和业务记忆；保存确认过的求职偏好、任务槽位和结果摘要，刷新或重启后仍可继续上下文任务。
- 业务闭环 Agent：工具可读取简历、JD、匹配证据、面试记录、机会阶段和行动项；建议可以定位回具体业务对象，避免“聊天回答”和“实际执行”脱节。
- 指定简历工作流：Agent 先让用户选择已保存简历，再进行本地优先诊断或生成可编辑草稿；草稿经用户修改和确认后才另存新版本，保证原始简历与事实不被静默覆盖。
- 安全的写操作边界：Agent 只能创建提议，服务端重新校验本地用户、实体所有权、字段范围、状态和幂等键；用户确认后才调用领域服务并记录执行回执。
- 多模型与无 Key 兜底：支持 GLM、DeepSeek、Kimi 等模型配置；无 Key 时可连续读取看板、职业目标、行动项和训练记录，综合输出求职诊断与行动优先级，明确展示本地模式且不伪装成模型调用成功。
- 工程化交付：实现版本化 SQLite 迁移、可恢复面试会话、证据驱动准备度、跨模块机会工作区、Edge/Chrome 响应式兼容和可移植 Windows 一键启动。

## 简历成稿

### 一页简历版

**职途 AI Agent 求职工作台（JobHunter）｜个人项目**

- 面向真实求职流程构建本地优先 Web 系统，串联职业目标、简历管理、JD 匹配、模拟面试、投递看板与复盘行动，解决求职信息分散、上下文重复输入和下一步不清晰的问题。
- 设计并实现自研 Agent Runtime，通过 `ContextBuilder` 重建权威上下文，结合分层持久记忆和 SQLite FTS5 检索历史结果，支持任务槽位追问、刷新/重启后续接和跨模块业务联动。
- 注册 21 个求职业务工具，接入指定简历选择/诊断/草稿、JD 解析、岗位匹配、面试评估、机会查询和行动项等能力；设计无 Key 确定性多工具规划，可综合看板、职业档案、行动项和训练证据输出下一步优先级。
- 设计“提议 → 预览 → 用户确认 → 领域服务执行 → 幂等回执”的 Agent 写入链路，服务端固定用户身份并校验实体所有权，避免模型直接修改业务数据。
- 支持 GLM / DeepSeek / Kimi 多模型配置和无 API Key 本地模式；完成 SQLite 迁移备份、可恢复面试状态、Edge/Chrome/移动端验证及 Windows 中文/空格路径一键启动。

### HR 快速阅读版

我做了一个真正融入求职流程的 Agent 系统。它不只是聊天，而是能理解当前简历和岗位，读取面试与投递记录，调用工具找到阻塞点，给出下一步，并把结果沉淀回系统。模型只能提出修改或推进建议，所有写入都要经过用户确认，因此同时强调可用性和安全边界。

### 面试口述版

这个项目最核心的不是接了哪个大模型，而是我把 Agent 放进了业务闭环。每次请求先由服务端根据页面模块和实体 ID 重建上下文，再从分层记忆和实时业务数据中检索相关信息。编排器在有限预算内决定是否调用工具，工具统一经过 Schema 和用户权限校验；如果要改简历、推进机会或创建行动项，就先生成提议，用户确认后才由领域服务执行。这样 Agent 的“智能”来自上下文、记忆、工具和状态管理的组合，而不是单轮 Prompt。

## 使用建议

- 技术岗位：保留 `ContextBuilder`、`ToolRegistry`、有界编排、Schema 校验、幂等回执等关键词。
- 产品/测试岗位：突出真实求职闭环、降级策略、跨浏览器验证、数据迁移和异常恢复。
- HR 初筛：优先使用“HR 快速阅读版”，再用“一页简历版”补充工程细节。
- 面试时不要声称使用 LangChain/LangGraph；准确表述为“基于 Flask + SQLite 自研 Agent Runtime”，并说明未来在多 Agent、跨服务长流程和可视化状态机需求出现时再评估 LangGraph。
